# Study Surfers — приложение Windows

React и 3D-сцена работают в окне Electron. FastAPI, SQLite, парсеры PDF/DOCX,
русские словари и Python упакованы PyInstaller. На компьютере игрока Python,
Node.js и браузер устанавливать не нужно. Поддерживается Windows 10/11 x64.

## Собрать приложение

На **сборочном компьютере** нужны Python 3.12 x64 с `py`, Node.js 24 и интернет
для первоначальной загрузки зависимостей и инструментов упаковки.

Дважды нажмите **`Собрать EXE.cmd`** в корне проекта. Или из PowerShell:

```powershell
.\scripts\build-desktop.ps1
```

В `release/` появятся:

- `Study-Surfers-0.1.0-Setup-x64.exe` — установщик с выбором папки и ярлыками;
- `Study-Surfers-0.1.0-Portable-x64.exe` — один запускаемый EXE без установки;
- `win-unpacked/Study Surfers.exe` — распакованная версия для проверки; её
  нужно переносить вместе со **всей** папкой `win-unpacked`;
- `build-info.json`, `SHA256SUMS.txt`, `python-packages.txt` — сведения о сборке,
  контрольные суммы и фактические версии Python-зависимостей.

Portable EXE при запуске распаковывает приложение во временный каталог. Это
занимает больше времени, чем запуск установленной версии. Личные данные остаются
в постоянной папке пользователя.

Для одного формата используйте `-Target setup`, `-Target portable` или
`-Target dir`. Например:

```powershell
.\scripts\build-desktop.ps1 -Target portable
```

Сценарий останавливается при любой ошибке. Он создаёт отдельное окружение
`backend/.venv-build` и копию фронтенда в `build/workspace`, устанавливает
зависимости по lock-файлам npm, проверяет
Python и TypeScript, запускает тесты, обновляет контракт, заново собирает Vite,
создаёт Python EXE и проверяет **замороженный** сервер до упаковки Electron.
Проверка EXE использует временные данные, путь с кириллицей и пробелами, случайный
свободный порт и PATH без установленных Python/Node. Проверяются ресурсы,
демо-колода, импорт/экспорт, сохранение после перезапуска, завершение и STDIO MCP.
После упаковки Playwright открывает настоящий EXE в отдельном профиле, проверяет
интерфейс, 3D canvas и остановку сервера при закрытии окна. Снимки сохраняются в
`output/desktop-smoke/`.

Также доступна ручная сборка в GitHub Actions: **Actions → Windows EXE → Run
workflow**. Результат скачивается одним артефактом, публикация релиза не выполняется.

## Как включать последующие изменения

Редактируйте обычные `backend/app`, `frontend/src`, `frontend/public` и прочие
исходники проекта, затем снова запускайте `Собрать EXE.cmd`. Сборка каждый раз
использует текущие файлы, включая новые модули `app`, и полностью пересобирает
интерфейс. Ручное копирование JS, моделей или Python-файлов в готовый EXE не нужно.
Зависимости добавляйте в соответствующий `package.json` с обновлением lock-файла
или в `backend/requirements.txt`. Дополнительные файлы Python вне `app` необходимо
явно добавить в `datas` файла `desktop/backend.spec`.

Перед распространением новой версии синхронно меняйте версию в корневом
`package.json`, `frontend/package.json` и `backend/app/__init__.py`, обновляя
lock-файлы через `npm install --package-lock-only` в обоих каталогах. После
изменения API перегенерируйте контракт: `python backend/scripts/export_contract.py`, затем
`npx openapi-typescript contract/openapi.json -o contract/api-types.ts`.

Закройте старое приложение и установите новый Setup EXE поверх него. Для portable
замените запускаемый файл новой сборкой. База и ключ установки лежат отдельно;
существующие миграции SQLite выполняются бэкендом при запуске. Удаление установленной
программы также сохраняет пользовательские данные.

## Данные и перенос существующей установки

EXE использует `%LOCALAPPDATA%\StudySurfers\data`. Внутри находятся база,
`installation.secret`, `mcp.token`, загруженные материалы, резервные копии и журналы.
Chromium хранит тему и локальные настройки в `%LOCALAPPDATA%\StudySurfers`.
Меню **Приложение → Открыть папку данных** открывает нужный каталог.

Существующие `Study Surfers.cmd` и `dev.cmd` по-прежнему используют `data/` рядом
с исходниками. Для переноса колод, статистики и подключений:

1. Закройте EXE и сервер, запущенный из исходников.
2. Если EXE уже запускался, сохраните копию `%LOCALAPPDATA%\StudySurfers\data`.
3. Скопируйте **всю** старую папку `data/` в этот каталог, не объединяя две
   разные базы и ключи. Сохраняйте `installation.secret` вместе с базой: он нужен
   для расшифровки ключей провайдеров.
4. Запустите EXE. Для MCP заново добавьте подключение из настроек приложения:
   путь к команде теперь указывает на встроенный EXE.

В сборку не входят `data/`, `.env`, ключи, локальное окружение разработчика или
данные Tentex. Автоматического переноса личной базы при компиляции нет.
Для отдельного каталога можно задать `SS_DATA_DIR` перед запуском EXE.
Для отдельного порта можно задать `SS_PORT` (например, `18765`); MCP использует
то же значение. По умолчанию порт остаётся 8765.

Локальный сервер принимает только loopback-адреса и отклоняет запросы API от
сторонних веб-страниц. Для явно включённого публичного туннеля из исходников
`scripts/launcher.ps1 -Public` передаёт домен в `SS_PUBLIC_HOST`; вручную можно
задать точное имя публичного домена (без протокола и пути). Доступ к локальным
настройкам через такой домен остаётся закрыт.

Импорт ограничивает размер запроса ещё при получении, а также распакованное
содержимое: коллекция Anki — до 128 МиБ, DOCX — до 96 МиБ суммарно и 32 МиБ на
часть. Чрезмерно большие таблицы и повреждённые файлы отклоняются с сообщением;
для большой колоды экспортируйте отдельный раздел без медиа.

## Запуск и диагностика

Electron запускает собственный сервер на `127.0.0.1:8765`, ждёт его готовности и
открывает окно. Повторный запуск переводит фокус в существующее окно. Если порт
занят сервером из `dev.cmd` или `Study Surfers.cmd`, закройте его перед запуском
EXE: приложение не подключается к неизвестному процессу и не завершает его.

При закрытии последнего окна закрывается канал к бэкенду, тот завершает фоновые
задачи и подключённые CLI. При аварийном завершении Electron канал также закрывается.
Журналы находятся в `data/logs/desktop.log` и `data/logs/backend.log`.

Для запуска оболочки из исходников после установки зависимостей:

```powershell
npm ci
npm run desktop
```

Нужно существующее `backend/.venv` с зависимостями. Этот режим использует тот же
каталог данных, что и EXE. Для обычной разработки с горячей перезагрузкой остаётся
`dev.cmd`. Сборка EXE устанавливает инструменты Electron в `build/desktop-tools`,
не переустанавливает рабочие `node_modules` и может идти параллельно с Vite
и открытой версией Electron из исходников. Изменения после создания сборочной копии войдут в
следующую сборку.

Для генерации через API достаточно настроить провайдера в приложении. Вход по
подписке ChatGPT/Claude требует отдельного официального CLI соответствующего
провайдера — это дополнительная интеграция, а не требование запуска игры.
STDIO MCP в EXE работает через `study-surfers-backend.exe --mcp` без системного
Python. Пакет Claude Desktop содержит нативный адаптер с его библиотеками, поэтому
он заметно больше пакета из исходников. После смены пути установки или portable
сборки заново установите MCP-подключение; старый путь мог стать недоступен.
Для portable бэкенд автоматически сохраняется в `%LOCALAPPDATA%\StudySurfers\runtime`:
его путь и MCP-подключение сохраняются между обычными перезапусками. Новое содержимое
подхватывается по хэшу файлов. Старые каталоги runtime можно удалить после закрытия
приложения и клиентов MCP, если больше не нужна соответствующая сборка.

Сборка создаёт EXE без цифровой подписи. Для публичного распространения можно
добавить сертификат подписи и включить `win.signExecutable`; сертификат и
пароли хранятся вне репозитория. Автообновление из интернета не настроено: новая
версия устанавливается новым Setup/Portable EXE.
