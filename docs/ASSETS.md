## Ночная магистраль

Байк, пилот, ремонтные роботы, маглев и архитектура созданы кодом специально для игры. Alet Hoverbike рассматривался как кандидат, но Sketchfab возвращает HTTP 403; его файлы в проекте не используются. Роботы созданы с шарнирным инструментом, без зависимости от внешних анимаций. Набор Quaternius остаётся возможным источником для будущих дополнительных моделей.

Из Space Station Kit используются `container-wide.glb` и `computer-wide.glb`: объединены в один GLB с meshopt, их геометрия запекается в сегменты, материалы приводятся к общей палитре. Звуки Kenney используются вместе с собственным Web Audio синтезом. Оригинальные лицензии находятся в `frontend/public/licenses/night/`.

Воспроизводимая подготовка: скачать бесплатные архивы со страниц Kenney, распаковать в `assets-src/night-maglev/station` и `assets-src/night-maglev/sounds`, выполнить `node frontend/scripts/prepare-night-assets.mjs`.

Исходники лежат в `assets-src/` (в git не попадают):

- `assets-src/kaykit-adventurers/` — `Rogue_Hooded.glb`, `Rogue.glb`, `Knight.glb`, `Mage.glb`, `Barbarian.glb` (по ~3,6 МБ), `LICENSE.txt`, `rogue.png` (превью).
- `assets-src/kenney-impact-sounds/` — `kenney_impact-sounds.zip` и распакованная папка `Audio/` с `License.txt`.

## Как пересобрать модели

```bash
npm --prefix frontend run assets
```

Скрипт `frontend/scripts/optimize-assets.mjs` (glTF Transform + meshoptimizer):

1. Из `Rogue_Hooded.glb` оставляет только клипы, которые играет `ModelRunner` (список `CLIPS` в обоих файлах должен совпадать). Он убирает каналы IK-контроллеров и масштаба, а также каналы, которые весь клип держат кость в позе покоя. Меши выбрасывает. Получается `kaykit-anims.glb`, около 190 КБ.
2. У каждого героя убирает анимации и снаряжение в руках (оружие, щиты, книги, кружку). Шапки, шлемы и плащи остаются. Получается `kaykit-<герой>.glb`, 105–125 КБ.
3. Сжимает геометрию meshopt (`EXT_meshopt_compression`, декодер встроен в загрузчик drei).

У всех героев набора один скелет из 41 кости с одинаковыми именами, поэтому общий файл анимаций подходит любому из них.

## Клипы и игровые состояния

| Состояние | Клип KayKit | Как задаётся время |
|---|---|---|
| Старт, портрет у арки | `Cheer`, потом `Unarmed_Idle` | по часам фазы |
| Отсчёт | `Idle` (стойка «готов») | по часам |
| Бег | `Running_A` (+ `Running_Strafe_Left/Right` при смене трека) | по фазе шага `runtime.stride`, поэтому ноги совпадают со звуком шагов |
| Прыжок | `Jump_Start` (толчок, первые 0,18 с) → `Jump_Idle` | по баллистике прыжка |
| Приземление | `Jump_Land`, присед | тем глубже, чем быстрее касание |
| Подкат | `Lie_Pose`, лёжа на спине ногами вперёд | вес = `slideDepth()`, та же кривая, по которой логика пускает под балку |
| Удар о препятствие | `Hit_A`, поверх основы | 0,6 с |
| Неверный ответ | `Hit_B` (слабо) + мотание головой | 0,55 с |
| Верный ответ | `Cheer`, только кости верха тела: ноги продолжают бежать | 0,6 с |
| Финиш | `Cheer` по мере торможения | по часам фазы |
| Проигрыш | `Death_A` | по часам фазы |

Персонажа выбирают в «Параметры → Персонаж». Вариант «Студент» — первая версия бегуна, собранная из примитивов кодом (`ProceduralRunner`); она ничего не загружает. Пока модель KayKit грузится, вместо неё бежит тот же «Студент».

Джетпак и гравикроссы созданы кодом, новых GLB и клипов не требуют. Все пять KayKit-моделей используют общую позу полёта; светящиеся подошвы следуют костям `footl` / `footr`. Процедурный бегун использует свои стопы. Ночные кольца, фазовый контур и щит работают с единым процедурным байком и пилотом независимо от выбранного героя.

## Зазоры с препятствиями

Размеры препятствий заданы в `frontend/src/game/engine/obstacles.ts`. Сцена рисует препятствия по этим же числам.

- **Барьер.** Высота доски `HURDLE_TOP` = 0,5 м. Взят, если ступни в момент прохода не ниже `HURDLE_CLEARANCE` = 0,7 м.
- **Балка.** Низ балки `BAR_BOTTOM` = 1,4 м. Пройдена только если бегун лёг почти полностью: `slideDepth ≥ 0,95`.
- **Вагонетки.** Крыша на высоте `DECK_HEIGHT` = 1,05 м. Заскок засчитывается, если ступни не ниже 0,65 м.

В dev-сборке `ClearanceProbe` в момент прохода берёт настоящие вершины модели с учётом скиннинга и пишет зазоры в `window.__clearance`. Проверка автопилотом:

```bash
node frontend/scripts/shots.mjs out 960 560 short low rogue-hooded '{"hurdle":1.8,"bar":1.6}'
node frontend/scripts/shots.mjs out 960 560 short low student '{"hurdle":7.8,"bar":8.7}'
```

Скрипт печатает `clippedWhileCleared`: если логика засчитала проход, а тело всё же задело препятствие, здесь будет непустой список. Последняя проверка дала пустой список у обоих бегунов для самого раннего и самого позднего засчитанного момента. Нижняя точка тела над барьером — от 0,68 м (доска 0,5 м). Верхняя под балкой — до 0,96 м у KayKit и до 1,28 м у «Студента» (балка 1,4 м).
